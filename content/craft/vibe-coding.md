# Vibe Coding 的技巧 — 用自然语言驾驭 AI 编程的心法

> 「未来的编程不是写代码，而是写意图。」

## 什么是 Vibe Coding

Vibe Coding 这个词是 Andrej Karpathy 提出的——前特斯拉 AI 总监、OpenAI 创始成员。他的意思是：你不再逐行写代码，而是用自然语言描述你想要的东西，让 AI 帮你生成代码，你负责审查、调整和引导。

听起来像是把程序员的活外包给了 AI？差远了。Vibe Coding 对程序员的要求不是更低了，而是转变了。你不再需要记住每个 API 的参数顺序，但你需要能精确描述你的架构意图、约束条件和预期行为。

## 核心心法：上下文为王

和 AI 编程最大的教训是：上下文（context）决定一切。

同样是「帮我写一个按钮组件」，如果你只说这一句，AI 会给你一个泛泛的 Button 组件。但如果你说：「帮我写一个按钮组件，用 React + TypeScript，使用 Tailwind CSS 样式，支持 primary/secondary/ghost 三种变体，需要处理 loading 状态和 disabled 状态，样式要和 globals.css 中定义的 CSS 变量一致」——你会得到一个可以直接用的组件。

好的 prompt 就像好的需求文档。模糊的意图产生模糊的代码。

## 我的 Vibe Coding 工作流

经过几个月的实践，我总结了一套工作流：

**第一步：明确架构**。在让 AI 写任何代码之前，先自己想清楚目录结构、数据流向、组件层级。不要让 AI 替你做架构决策。

**第二步：分步指令**。不要一次让 AI 做太多事情。「帮我搭建整个博客」的效果远不如「先帮我实现 Markdown 解析函数，输入是文件路径，输出是 frontmatter 和内容」。

**第三步：提供约束**。告诉 AI 不要用什么（「不要用 any 类型」「不要用内联样式」「只用 TECH_STACK.md 里的依赖」）和应该遵循什么（「参考现有的 PostCard 组件风格」）。

**第四步：审查与迭代**。AI 生成的代码不要直接复制粘贴。逐行读，理解每一行为什么在那里。看不懂的地方让 AI 解释。这个审查过程本身就是学习的过程。

## 常见陷阱

**过度依赖**：让 AI 写了代码但不理解它。当出 bug 的时候你会发现自己根本不知道怎么改。

**上下文丢失**：长对话中 AI 会「忘记」之前说过的话。重要的约束要反复强调，或写在系统指令里。

**风格不一致**：AI 每次生成的代码风格可能不同。需要建立一个项目规范文件（就像本项目的 copilot-instructions.md），让 AI 每次都参考。

## 一个反直觉的结论

Vibe Coding 让我成为了一个更好的程序员。不是因为我写了更多代码，而是因为我被迫把以前模糊的想法用精确的语言表达出来。会不会写代码不重要，会不会清晰地表达意图，才是新时代最重要的编程技能。
